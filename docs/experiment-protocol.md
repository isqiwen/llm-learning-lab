# 实验规范：从可运行到可信结论

本文件是本仓库提出的实验工作规范，不是任何课程的官方评分细则。目标是避免数据泄漏、错误测量、挑结果和无法复现。

## 1. 实验前登记

每个实验使用 `EXP-YYYYMMDD-short-name`，从 templates/experiment.md 建记录，链接一个 Issue。启动前记录：问题、可证伪假设、主指标、基线、控制变量、唯一主要改动、数据划分、模型/代码版本、seed、预算与停止条件。

探索性 pilot 与确认性实验分开；pilot 后可以修改假设，但必须记录改动，不能把事后发现冒充预先假设。开始确认性实验前冻结评估器与主要配置。

## 2. 数据与评估

记录来源、许可、版本/哈希、采集/处理步骤、样本/文档/token 数。先按文档/实体等合理单位划分，再训练 tokenizer 或模型；避免同一来源片段跨集合造成泄漏。适用时检查精确和近重复。

只用 train 拟合，dev 调参，test 用于冻结后的最终评价。测试集访问留记录；如果反复用 test 选择模型，就承认它已经成为 dev，并另建 held-out 集。

固定模板、tokenizer、有效 label 和截断规则。Per-token loss/perplexity 必须按有效 token 计权；不同 tokenizer 下的数值不能直接当作公平模型排名。标准 benchmark 可能出现在预训练中，报告污染风险，不把公开评测成绩等同未见任务泛化。

## 3. 正确性先行

数学/训练：形状、mask、dtype、梯度、保存恢复、空样本/极端值。Attention 测试包括未来 token 不影响前缀输出，autograd 与可信 reference 对照。数值容差在看结果前声明；不同 precision/shape 使用合理阈值并说明依据。

系统：先比较输出与梯度，再比较速度；不得用错误输出、跳过工作、改变精度或减少有效计算来制造加速。CPU 进程通信测试只能证明相关正确性，不能替代 GPU/NCCL scaling 实测。

Agent：可见测试、隐藏测试与最终评价器分离。Agent 无权修改 evaluator/答案，也不能读取测试集；评估受污染的轨迹单独标记。

## 4. 公平对照

训练工作先选择公平性口径：相同有效 tokens、相同 FLOPs 或相同预算/时间。不同口径回答不同问题，不能声称同时控制了不可能全部相等的量。记录 baseline 调参预算，不能给新方法更多搜索机会却只比较单次最佳结果。

Agent 至少区分 single-shot、同预算 repeated sampling 与有反馈的方法。报告实际选中解的成功率与成本；oracle pass@k 只反映候选中是否有正确解，不代表系统能选对。任务难度和采样相关性存在时，不能直接使用单个平均 p 的独立重复公式解释全部提升。

消融先移除一个组件，再解释差异；必要时检查组件交互。共享同一固定任务集做配对分析，避免用不同难度数据集比较。

## 5. 不确定性与报告

训练建议从至少 3 个预先固定 seeds 起步，并同时展示各 seed；这只是最低实践起点，不是统计功效保证。根据方差、效应大小和预算决定追加重复。小样本不足时直接报告不确定性，不能将不显著等同证明无差异。

任务成功率报告分母、任务构成与区间；有重复采样时按任务组织分析，不把同一任务的多条轨迹伪装成独立任务。可使用任务级配对 bootstrap 等适合设计的方法，并说明假设。

报告均值/中位数、分散程度、主指标与预先约定的最小有意义效应。保留所有已运行配置、失败、超时、NaN、OOM、无收益结果与搜索预算，不只发布最佳 seed 或最佳样例。研究目标是有效证据，不是每次跑赢 baseline。

## 6. GPU / 推理性能测量

记录设备型号、驱动、运行时、框架/编译器版本、precision/TF32、shape/stride、batch、序列长度、并发、输入输出长度分布与模型版本。计时前 warmup，显式处理异步执行与同步；区分首次编译/冷启动和稳态，说明是否包含 H2D/D2H 与数据加载。

分别报告 prefill/decode、TTFT、ITL、tokens/s、p50/p95 与峰值内存。吞吐按实际生成 token 数统计，不能混用请求数、输入 token 和输出 token。固定 workload 与系统状态，交错或随机测试顺序，检查频率/温度/其他负载；尾延迟需足够请求数。

不同显卡的绝对 latency 不作直接算法优劣证据。没有相同硬件时描述相对结果和差异，不硬凑论文数值。原始测量可重算，图表生成脚本入库。

## 7. 预算、存储与安全

默认外部付费预算为 0，必须由本人明确批准后才使用云 GPU/API。建议逐级：CPU 单元测试 → 分钟级 smoke → 小型 pilot → 审核结果后确认性实验。每个运行必须有限时/最大 steps/tokens/费用上限与停止条件；没有自动无限搜索。

Git 保存小型配置、脚本、数据卡、分析和可分享指标；大权重、原始数据、缓存、轨迹和 checkpoints 保存于外部存储。记录校验值和访问方法，避免在公开记录中暴露私人存储地址。至少给不可重建数据做独立备份。

执行模型生成代码时使用隔离环境和最小权限，默认不联网，不挂载 docker.sock、SSH 私钥、真实账户数据或生产目录；设置 CPU/内存/进程/时间限制。容器不被当作绝对安全边界，高风险任务使用更强隔离。

## 8. 完成证据

实验完成需包含：Issue、方法说明、代码 commit、锁定环境、数据版本、配置、运行命令、原始指标、统计脚本、结果表、失败记录、局限与下一步决定。能由本人解释，并能从干净环境复跑。未执行的实验必须标为 planned/not run，不能填写拟造指标。
