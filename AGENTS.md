# Guidance for AI assistants

This is a learning and research repository, not a system for outsourcing mastery.

## Scope

Maintain plans, resources, issue structure, tests for management tooling, and reviewable research infrastructure when asked. Respect the user's requested change scope. Read current repository content before editing, preserve unrelated work, and prefer small auditable commits.

## Learning integrity

Do not mark learning complete because you generated code or notes. Core coursework should be implemented and explained by the learner; give conceptual explanations, incremental hints, debugging help and review. Follow each course's current AI/reference/publication rules. Keep restricted assignment solutions out of this public repository.

## Evidence

Never invent experiments, benchmark numbers, hardware access, test passes, citations or completion. Distinguish local unit tests, mocked integration tests and actual remote/GPU runs. A negative or inconclusive result is valid if the protocol is sound. Do not change a success criterion after seeing the result just to claim improvement.

## Experimental safety

No paid API/GPU runs without explicit budget approval. No open-ended searches or privileged execution of generated code. Do not upload credentials, private/company data, model weights or restricted datasets. Keep hidden evaluators outside the agent-writable workspace.

## Tracking

Issue state and Project Status are not equivalent without a configured workflow. Textual Parent/Depends on is not a native GitHub relationship. Report exactly which remote writes succeeded. Do not claim Project fields or views were created when only a script/specification was committed.

Planning metadata lives in planning/project.json; existing Project values must not be silently overwritten. PROGRESS.md is an evidence ledger, not a forecast.
